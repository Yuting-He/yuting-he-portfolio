# Watt hackathon dashboard：自助情景 Showcase 与证据层实施方案

实施状态：本方案的 P0 已进入交付实现；实际入口、复现命令和验证范围见 `P0_DELIVERY.md`。以下内容保留为实施前设计依据。

评审日期：2026-10-24。按用户最新要求修订：P0 默认入口改为无需口头讲解的动态情景 Showcase，现有 dashboard 通过选项卡深入阅读。本文件是下一步实施方案；本次仅更新方案，未修改运行代码。

## 交付目标

默认交付增加可独立观看的 **Showcase**，在 60–90 秒内展示“工况变化 → 收到疑似异常线索 → 选择检查目标与无人机 → 飞行和驻点检测 → 更新判断与后续行动”。打开即能知道问题是什么，观看过程中不用自己选情景、调时间、找线路或寻找算法页。

交付目标从静态的“一个结论与证据快照”调整为“一个正在展开、每一步都有理由的行动闭环”。前一版提出的版本一致、参数透明、合成来源、Unknown 与验证边界仍属于 P0。地图和实施路线成为 Showcase 的主要视觉，概率变化在产生证据的对应阶段突出显示。

建议价值主张：**用天气条件下的正常基线与可审计的概率推断，帮助有限的移动传感器决定先查哪里、何时交给人。** 减少不必要的现场核查是待验证目标，必须同时观察漏检与发现延迟。

## 建议的信息架构与视觉布局

顶层导航调整为 **Showcase（默认）｜Dashboard｜Validation**。

- **Showcase**：面向第一次访问者，自动叙述一个完整行动案例。
- **Dashboard**：保留目前 Live operations、Evidence & baseline、Decision network、Weather & provenance、Audit & comparison 的完整内容，便于专业评委深入查看。旧 Official challenge 和 Synthetic laboratory 仍在高级工作区入口。
- **Validation**：展示当前版本的验证范围、指标、参数来源和已知短板，不把静态评估混作动态任务成效。

### Showcase 布局

1. 顶部：一句问题与价值主张，例如“风后出现疑似线路异常，五台移动传感器应该先去哪里核查？”并保持“合成情景回放 / 官方地图 / 未实测校准”短标签。
2. 顶部下方：六幕进度导航“工况 → 线索 → 选机 → 执行 → 检查 → 更新行动”，始终显示当前幕与模拟时间。第一屏就能读到整条解决路径，不要求先看完动画。
3. 左侧约 60%：真实挑战地图和当前相关机位、目标、路线；只高亮当前任务，其他线路和设备弱化。地图视野随章节平滑聚焦，不每帧跳动。
4. 右侧约 40%：固定位置的解释卡，每幕只回答三件事——**发生了什么 / 为什么这样判断 / 系统下一步做什么**。每项一句话，关键文字无需 hover。
5. 底部：播放/暂停、上一幕/下一幕、重播；可直接点章节。右侧卡保留“查看本步证据”，连到 Dashboard 对应资产、任务和时间快照。
6. 到达检查阶段，解释卡将视觉重点换成同窗概率变化与结果解释；其他阶段不提前展示检查结果。最后停在“检查发现与后续行动”的明确结尾，不自动循环。

不同时显示五张大设备卡、全部任务、全部航线、四个信号图和完整 BN。需要比较选机时，在决策卡中放“被选设备 + 一项未选原因”，完整五机候选表在 Dashboard。

视觉规则：阶段标题约 28–32px，正文约 16px，辅助标签至少 14px；概率主值仅在证据更新阶段放大。红色表示需及时人工处理，琥珀表示待核查，灰色表示 Unknown，颜色均配文字。未观测线路不能因情景脚本中的隐藏故障而提前变红。

### 自助观看与页面切换

- 首次访问默认无声播放一遍，目标时长约 75 秒；同时提供暂停、逐幕和直接定位，不能以声音或口头讲解承载必要信息。少动效偏好时显示静态章节，全部标题和下一步入口仍可用。
- 事件回放可以压缩等待：明确显示“已跳过无关键变化的等待”和推进后的模拟时间。观众时间与模拟分钟分开，动画快慢不改变飞机的模型速度、里程或任务结果。
- 点击“查看本步证据”立即暂停 Showcase，并同步 `asset_id / operation_id / snapshot_id / simulation_time`。Dashboard 显示所选历史快照与来源，不能悄悄跳到任务最终状态。
- 返回 Showcase 保留当前幕并停在原位置；重播仅重置回放游标。用户的自由探索模拟实例、原有任务和设置保持独立。
- 实现时只执行当前顶层页面的活动逻辑。不要仅用会同时执行隐藏内容的 tab 把原来的自动推进 fragment 包起来，导致阅读证据时后台仍在推进任务。

### 深入证据层

Dashboard 保留已有 BN 变量图、8/16 联合状态、条件基线、检查快照、动作成本、五机候选与任务审计。通过统一快照适配层显示 Showcase 当前一步的只读证据；原有可操作工作台仍可明确选择进入。

Validation 先区分“计算正确性、合成场景表现、待实测校准”，再展示报告和参数来源。首屏的合成与未校准标签始终保留，不能全藏入此 tab。

## 60–90 秒情景分镜

主案例采用当前 `dynamic / seed 42` 的真实模拟事件，选取 LINE_058 从未覆盖线索到现场检查的过程。模拟必须从 T+0 正常运行生成记录；展示从相关工况开始的片段，不能删掉早期任务后再声称路线不变。

| 章节与建议观看时长 | 当前版本事件锚点 | 页面动作与自解释文案重点 |
|---|---|---|
| 1 工况与覆盖，约 8 秒 | LINE_058 报告到来之前的已接收天气与机队状态 | 展示风后环境、五台设备和局部覆盖；“未覆盖不等于健康，我们需要决定下一处核查位置。” |
| 2 收到线索，约 10 秒 | T+46 收到 LINE_058 高优先级现场报告 | 高亮线路与报告来源；“有人报告异常运动，但这里没有实时观测，需要补充证据。” 不显示已确认故障 |
| 3 选择目标与无人机，约 12 秒 | T+47 派遣决策快照 | 高亮 Drone 5；“Drone 1 虽只需 3 分钟，但原站 LINE_026 仍有异常，需保留观测；Drone 5 当前可行。”此时没有现场 88.4% 后验 |
| 4 执行路线，约 15 秒 | Drone 5 从 LINE_009 于 T+47 出发，T+56 抵达 LINE_058 | 显示约 21.3 km、40 m/s、9 个模拟分钟；区分计划虚线、已飞实线、当前位置和抵达时间 |
| 5 驻点检查，约 18 秒 | T+56–60 稳定检查；T+58 发出人工现场检查请求；T+60 收到 RGB clear | 到达后才使用稳定观测，持续残差触发人工复核；收到影像后展示同窗 88.4% → 55.5%。说明 clear 不代表排除故障 |
| 6 判断与后续行动，约 12 秒 | T+60 推荐 inspect_sensor；T+58 创建的现场人工请求仍 open | “影像未见对应线索，但风险未清除；建议检查传感器，已发出的现场复核仍待处理。”LINE_015 解除等待检查结果的依赖，仍因可行性不足延后 |

以上锚点用于本次方案核查。实现时由冻结交付版本的事件记录生成章节，不在 UI 写死出发、抵达、结果时间。若版本变更导致事件变化，重建数据和文案；不能移动事件来迎合演示脚本。

主线结束时可提供“继续看后续调度”，展示当前版本 LINE_015 于 T+71 才起飞的后续过程。T+20/29/32 报告纠正/撤销、健康强风和缺测案例放可选章节或 Dashboard，不挤入默认 75 秒主线。

路线采用当前仿真的地理点间移动模型，图例标为“模拟航段”。不把线路几何当成已验证电气拓扑，也不把示意路线称为经过避障、禁飞区或真实空域验证的航线。

## 用一个实际案例解释算法

当前代码内存重放 `TwinSimulation('dynamic', seed=42, autonomous=True).advance_to(60)` 的 LINE_058 案例得到：

- 窗口先验约 **4.9%**。
- 同窗遥测后约 **88.4%**。
- 加入 RGB `clear` 巡检后约 **55.5%**，降低约 **32.9 个百分点**。

这些数值放在 Showcase 的检查结果阶段。它们是当前窗口模型在合成假设下的输出，绝不是实测故障率或已校准置信度。UI 必须读取当前模型产生的冻结快照，不能把上述文字中的数值硬编码成演示状态。

T+47 出发时 LINE_058 没有现场遥测，任务评分里的 `current_bn_risk` 与 `value_of_information` 都是 0；派遣由收到的高优先级报告和覆盖缺口驱动。T+56 到达后才出现本地模型判断；T+60 的 88.4% 不得拿来解释 T+47 的出发。地图和解释不读取模拟器的隐藏故障标签。

说明顺序：

1. 风大会改变健康状态下的震动，所以先计算天气条件下的预期值和波动范围。观测偏离正常范围才进入后续假设比较。
2. BN 同时考虑机械异常、热异常和传感器/安装问题。它们可同时存在，不能用互斥饼图表现。运行状态未知时同时枚举带电与不带电分支；已知时固定该状态。
3. 同一传感器窗口加入一份有效检查结果，可以隔离这次检查对判断的影响。`clear` 表示未见对应可见线索，不能翻译成“已排除故障”；RGB 尤其不能独立排除热异常。
4. 在这个冻结窗口里，三阶段对比始终使用相同读数、基线与先验。它不是三个时刻累积形成的置信度增长。
5. 下一步行动读取该窗口的真实推荐或任务记录，并注明它是“当前建议”“已执行检查”还是“尚未解决的人工请求”。展示行动成本比较与实际可行性，不能仅凭 55.5% 编写一个不存在的派遣结果。

制作阶段从当前版本运行一次完整情景，逐事件保存冻结快照；观看时只移动独立的回放游标。页面刷新、tab 切换和预览不生成新检查、不改变决策、不覆盖用户工作台任务。单个 operation 的 `human_required=false` 不能替代资产级人工请求检查；T+60 仍须展示 `alert-002` 的未解决状态。

## 将可靠性作为方法证据展示

| 层次 | 可以展示什么 | 当前边界及应补工作 |
|---|---|---|
| 计算正确性 | 精确枚举、概率归一化、同窗 Bayes 重建、重复证据与时效检查 | 单元测试支持实现一致性，不能替代识别效果验证 |
| 模型可解释性 | 观测、正常范围、残差、先验/似然来源、联合假设、行动比较 | 图结构手工指定；条件依赖不是已证明的物理因果关系 |
| 统计可靠性 | 固定测试协议下的误报、漏检、漂移识别及概率可靠性 | 现有数据为合成；真实标注数据与独立场景留出仍需补充 |
| 行动可靠性 | 约束是否执行、何时交给人、未知是否保留、审计是否一致 | 轨迹跑通不等于动态任务性能、最优路线或实际节省 |

首屏可用三条可核查机制解释方法选择：**缺测保持 Unknown；相关证据不按独立证据重复计算；检查有时效并能追溯原始快照。** 详页解释为何暂时保留窗口 BN：相邻窗口残差明显相关，状态转移率缺乏实测标定，直接累乘会制造过度置信；调度可以利用持续性规则，但不把这些规则说成递归 DBN。

参数来源明确分为：官方资料、独立健康合成样本拟合、手工演示假设、待实测校准。3,600 条健康合成样本是基线拟合记录，不是 3,600 次真实故障验证。正常参考范围不能改名为故障概率的置信区间。

### 必须完成的版本一致性工作

- 冻结本次交付的模型、基线、检查模型、行动策略、阈值和情景配置；记录源码指纹或提交标识、运行命令、seeds 与时刻。
- 用冻结版本重跑静态评估、核心案例和必要的动态回放，并同步截图、README、验证说明和讲稿。
- `validation_summary` 比较报告与当前运行的版本/配置；不匹配时显示“此报告属于旧版本”，不得继续显示为当前性能。
- 预计算验证摘要，正常打开评审页不触发完整基准计算。

### 下一步应补的比较实验

按同一数据、同一派遣约束、同一行动成本协议比较：原始固定阈值、条件基线残差阈值、完整 BN。另做关闭传感器故障解释或忽略机械相关性的单项消融，回答“每一层方法解决了什么问题”。这些是计划中的比较，完成前不能写成已有优势。

至少覆盖：健康强阵风、短时噪声、机械/热异常、测量漂移、缺测、运行状态未知、巡检误报/漏检、证据过期。参数和阈值在留出测试之前冻结；按独立情景/轨迹/设备分组，不把相关相邻窗口随机拆进训练与测试。

优先展示两个行动结果：不必要人工升级次数，以及事件漏检/发现延迟；同时提供分类误报/漏检作为诊断。健康任务中的升级次数按任务或有效观测时长给分母；事件延迟同时列出未发现数量，不能只报成功发现事件的平均时间。Unknown 不得算作真阴性。

概率层面补 Brier score、可靠性曲线及每个分箱样本数；样本少时直接标注证据不足。Brier score 同时受区分能力和校准影响，不能单凭一个分数宣称概率已校准。所有合成实验只能支持仿真条件内的结论。

字段来自已有 `operations / decision_explanation / replans / inspection_history / assessment_history / audit`，并复用 `explain_asset()` 和 `probability_stages()`。每个阶段记录当时可见的快照，不能只存任务最终状态再倒填过去。解释文案使用确定性模板；对模型推断、行动建议和执行状态不增加第二套展示计算。

路线插值只改变图标显示位置，起飞、到达、检查完成和充电状态沿用日志。同窗概率对比仍以冻结读数计算，不把出发与抵达的不同观测窗口拼成一次检查更新。未来计划可显示为“计划”，未收到的结果不能出现在当前幕的卡片、tooltip 或证据详情里。

交付数据预先打包并缓存；首屏无需实时重跑 T+0 到 T+60，也不在线执行完整验证。版本或配置失配时不静默播放旧故事。目标访问环境需要确认评委能直接打开交付网址，而不是仅验证开发机 localhost；部署平台选择和上线在真正实施交付时处理，本轮不发布服务。

## 演示与验收

默认 Showcase 约 75 秒自动叙述，不依赖讲者。前 10 秒明确问题、覆盖缺口和整体流程；完整播放结束明确检查结果与仍待处理的行动。想深入的评委可在任意一步暂停并切入 Dashboard，Validation 提供当前版本的证据与边界。

若保留三分钟现场讲稿：先让 Showcase 用 75 秒完成主线，再用约 60 秒打开当前步骤的 BN/选机证据，最后约 45 秒解释验证与已知短板。讲稿与自助页面共用同一事件和文案来源。

验收标准：

- 1440×900 在 100% 缩放下，首屏直接看到任务问题、章节、地图、解释卡和控制；1280×720 下关键叙事与控制仍可读，窄屏按地图与解释卡堆叠。
- 初次打开即有完整首帧和问题说明；主线无需选 seed、时间或线路，无需开启音频。预加载目标为测试设备上 3 秒内呈现可读首帧；未达标则优化数据体积和加载路径，不用空白模拟等待替代。
- 无讲解观看不超过 90 秒后，陌生评审能回答：为什么查 LINE_058、为什么选 Drone 5、从哪里飞到哪里、检查如何改变判断、还有什么行动未完成。
- T+47 不显示 T+60 才取得的 88.4% 后验；T+56 前不把途中数据用于该线路诊断；T+58 人工请求按时显示；T+60 clear 不自动解除该请求。
- 计划/飞行中/已抵达/检查中/已检查明确区分；路线、速度、时长与日志一致；跳过等待不改变约束或模拟任务时间。
- Showcase、Dashboard、冻结快照与导出 JSON 的同一指标一致；概率变化使用百分点标注。
- 切页后自动暂停；返回保留章节；重播仅改变游标，不重复派遣或重复加入证据；历史回放和当前自由探索标注清楚。
- 缺测、过期、无效质量保持 Unknown 或明确被排除；人工请求被确认后仍保留未解决状态。
- 检查结果、两条关键证据、推荐与任务状态绑定同一资产和时间范围，不拼接不同快照制造故事。
- 加载故障、版本失配和少动效模式下仍能阅读章节摘要，不显示空白页或旧版本性能冒充当前结果。
- 当前运行逻辑和相关回归仍通过；至少做一次实际浏览器的首访、自动播放、暂停、跳幕、查看证据、返回、重播和窄屏检查。
